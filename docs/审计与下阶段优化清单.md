# 元境 · 代码审计与下一阶段优化清单

> 审计日期：2026-10-19 ｜ 审计方式：源码走读（基于已改造版本 0.30.4）
> 优先级：**P0** 必须修（安全/正确性）→ **P1** 应做（体验/合规）→ **P2** 可做（增强）

---

## 一、P0 · 必须处理（安全与正确性）

### 1. API 密钥安全存储 🔴
- **现状**：需要审计 `SharedPreferences` 里 API Key / Token 的存储方式。目前代码未见加密存储调用（需进一步确认）。
- **风险**：手机 root 或备份可提取明文密钥 → 盗刷你的 API 额度。
- **方案**：改用 `EncryptedSharedPreferences`（AndroidX Security）或 Android Keystore 加密后再落盘；内存中用完即清。
- **工作量**：约 0.5 天。

### 2. 更新检查指向专用仓库 🔴
- **现状**：`GITHUB_REPO=xxm`（用户现有公开仓库，与元境无关）。
- **问题**：发版时会污染 xxm 仓库的 Release 列表；用户访问关于页看到的是不相干仓库。
- **方案**：新建"元境"公开仓库（如 `zihan8023/yuanjing`），改常量指向它；后续所有 Release 发到该仓库。
- **工作量**：0.5 天（含建仓+推送源码）。

### 3. 本地模型文件完整性校验 🔴
- **现状**：下载有断点续传 + 白名单校验，但未见下载后对 GGUF 文件做哈希校验。
- **风险**：网络中断导致文件损坏 → llama-server 加载崩溃或输出幻觉。
- **方案**：下载完成后校验 `sha256`（在模型注册表里内置每档模型的官方哈希），不符则提示重新下载。
- **工作量**：0.5 天。

## 二、P1 · 应做（体验 / 合规 / 稳定性）

### 4. 包名迁移 `com.iqge` → `com.yuanjing` 🟡
- **现状**：品牌已改"元境"，但包名仍是 `com.iqge`。
- **影响**：商店上架、隐私政策、第三方 SDK 统计、深链都会暴露旧品牌；长期不利于品牌一致性。
- **方案**：分步迁移（manifest + ApplicationId + Provider authority + 反射调用点逐一替换），用脚本批量替换后全量回归测试。
- **工作量**：1-2 天，需排期（风险中，放发版淡季做）。

### 5. 权限门（工具执行）体验细化 🟡
- **现状**：工具执行过权限门（高风险命令需确认），但策略是全局开关。
- **方案**：按命令分类记忆授权（"始终允许/仅本次/总是询问"），高风险命令（rm -rf、curl 上传、改权限）强制二次确认；白名单命令（ls、cat 等）免确认。
- **工作量**：1 天。

### 6. 通知渠道与 Android 13+ 适配 🟡
- **现状**：保活通知用自定义频道（已改"元境后台保活"），但需确认 `POST_NOTIFICATIONS` 运行时权限在 Android 13+ 的申请逻辑。
- **方案**：启动时检测并引导授权；悬浮球同样处理 `SYSTEM_ALERT_WINDOW` 引导（已有 `overlayShell` 机制，补引导文案）。

### 7. 错误上报与日志兜底 🟡
- **现状**：异常多为 toast 提示，无日志落盘。
- **方案**：`Logcat` + 崩溃写入 `files/logs/`，设置页提供"导出日志"按钮（方便用户反馈问题）。
- **工作量**：0.5 天。

### 8. 隐私与合规 🟡
- **方案**：上架商店前准备隐私政策（说明：本地模型离线运行、云端调用 API、收集哪些数据）；`targetSdk` 升到 34/35 时过一遍行为变更清单。

## 三、P2 · 可做（增强体验）

### 9. 本地模型智能路由增强
- 按"当前任务类型"分流：纯代码问答 → 本地小模型（省流量）；联网/工具任务 → 云端。
- 下载前预估（档位+可用内存）已实现，可加"下载后自动加载"开关。

### 10. UI / 动效打磨
- 对话框进出动画已用 `UiMotion.dialogIn`，可加列表删除/下载进度条动效；
- 主题可加第 3 套"纯 OLED 黑"省电模式（深色屏手机）。

### 11. 插件与扩展市场
- 现有多模型 Provider 抽象（`ModelProviders`），可扩展为"插件式"：用户导入自定义模型/工具脚本，社区共享。

### 12. 多语言
- 全部文案目前硬编码中文，抽到 `strings.xml` 后支持英文版（海外用户）。

## 四、发布流程建议（每次发版 checklist）

1. `versionCode` +1、`versionName` 递增（当前 0.30.4 → 0.31.0）
2. 更新 `GITHUB_REPO` 指向元境仓库 → 打 Release（tag = 版本号，附 APK + 更新日志）
3. 手机实机验证：全新安装 / 覆盖安装 / 悬浮球权限 / 本地模型下载与推理
4. 导出 debug 签名换 release 签名（keystore 已生成：`app\signing\iqge-local-dev.jks`）
